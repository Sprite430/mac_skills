# PB 需求文档助手

用于在需求沟通完成后生成简洁 PRD，给后续 `pb-server-developer` 开发和 `pb-delivery` 交付使用。

## 强制规则

1. 只生成需求文档，不修改业务代码。
2. 输出必须使用中文。
3. 文件保存到 `docs/requirement/YYYY-MM-DD-<需求名称>-prd.md`。
4. 需求文档只描述“要做什么、涉及哪些文件/范围、最终如何验证”，不要写具体代码实现逻辑。
5. 如果用户信息不完整，先补问缺失项；不要凭空编造业务细节。
6. 如果用户已经提供足够信息，直接生成文档。

## 和其他 Skill 的配合

- 需求沟通完毕后，使用本 skill 生成 PRD。
- 开始开发时，使用 `pb-server-developer` 按 PRD 和目标项目实现。
- 开发测试完成后，使用 `pb-delivery` 读取 PRD 并生成交付目录。

## 必须收集的信息

至少确认以下四类信息：

1. 需求名称：用于标题和文件名。
2. 自然语言需求：描述用户希望系统支持什么能力、在哪个业务场景使用。
3. 涉及文件或影响范围：页面、JS、Controller、Service、DAO、配置、SQL、自动任务、系统参数、数据库表等；不知道具体文件时写“待开发时确认”。
4. 最终验证方式：从业务结果角度描述如何确认需求完成。

可选确认：

- 目标项目：2.x 个性化、3.x 个性化、产品化基线或用户指定路径。
- 所属模块/银行/地区。
- 是否需要兼容 2.x 或 3.x。
- 是否涉及新增按钮、后端接口、新页面、自动任务、系统参数、配置文件参数。

## 输出文档结构

```markdown
# <需求名称> PRD

## 需求描述

用自然语言说明本次需求目标、业务背景和用户期望结果。

## 影响范围

| 类型 | 内容 | 说明 |
|---|---|---|
| 页面 |  |  |
| 前端 JS |  |  |
| 后端接口 |  |  |
| Service/DAO |  |  |
| 数据库/SQL |  |  |
| 配置/参数 |  |  |
| 自动任务 |  |  |

不存在或暂不涉及的类型可以写“无”。不确定的文件写“待开发时确认”。

## 不包含内容

- 不描述具体代码实现逻辑。
- 不写类内部方法细节。
- 不写未经确认的数据库字段和 SQL。

## 验证方式

- [ ] 从用户入口验证功能可用。
- [ ] 验证正常业务数据结果正确。
- [ ] 验证异常或边界场景符合预期。
- [ ] 验证相关配置、参数或 SQL 生效。

## 备注

记录用户额外约束、版本要求、部署注意点或待确认事项。
```

## 工作流程

1. 根据用户描述判断信息是否足够。
2. 如缺少需求名称、涉及范围或验证方式，只问必要问题。
3. 生成 `docs/requirement/` 目录。
4. 写入 `YYYY-MM-DD-<需求名称>-prd.md`，日期使用当前本地日期。
5. 回复文档路径，并简述需求、影响范围和验证重点。

## 文件命名

- 日期格式：`YYYY-MM-DD`。
- 需求名称保留中文，去掉 `/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|` 等不适合文件名的字符。
- 示例：`docs/requirement/2026-05-25-零余额退款新增复核按钮-prd.md`。
